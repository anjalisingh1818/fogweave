# Decisions

One line each: what was chosen, and why. Newest last.

- **Client stack:** IWSDK `@iwsdk/core` 1.0.1 (three r181 via super-three) and Vite 7.3.7, both pinned. The scaffold already used them; IWSDK is Meta's WebXR SDK with an emulator built in.
- **Emulator QA:** IWER 2.6.0 (bundled with `@iwsdk/vite-plugin-dev`) drives scripted hands through its remote-control API (`set_transform`, `look_at`, `animate_to`, `set_select_value`). These are scripted hands, not people, and not a Quest.
- **QA browser:** Playwright 1.64.1 (pinned) runs headless Chromium. The Claude Desktop browser pane throttles hidden pages to about 30 fps, so its frame numbers are useless.
- **HTTP dev mode:** `FW_HTTP=1` serves `http://localhost`, which still counts as a secure context, for desktop emulator QA. The default self-signed HTTPS is kept for headsets.
- **One driving system, no per-node ECS entities:** the web is drawn with InstancedMeshes (cores per type × layer, verdict rings, glows, an enlarged invisible hit mesh) and a few LineSegments. This keeps draw calls flat as the web grows.
- **Force layout:** a small in-house 3D force layout (`src/layout/force.js`) runs in a Web Worker. It is deterministic: seeds come from id hashes, so the same web always lands in the same shape, and results are cached by graph shape. d3-force-3d was not needed for 150 nodes.
- **Bubble shape:** a wide, shallow ellipsoid (x1.25, y0.8, z0.5) in front of the seated head. Viewed from one point, a sphere overlapped itself in depth. The radius grows (up to 1.6x) for big webs.
- **Cards:** canvas-texture panels with one mesh each. Buttons are hit-tested from the pointer's `uv`, so a whole keypad is one draw call and one interactable. Fonts are system fonts, so no font assets are needed.
- **Keypad is ray-pinch only:** with `PokeInteractable` on the panel, IWSDK 1.0.1 swallowed ray pinch-selects (seen in scripted QA). A pinch keypad is what the brief asks for. Retest poke on a Quest.
- **Prop tap fallback:** IWSDK sets `pointerEventsType = { deny: 'ray' }` on grabbables, so a far pinch cannot reach the Coin or Locket. Two fallbacks cover it:
  - a quick pinch-and-release on the prop (under 450 ms and under 4 cm of movement) counts as a tap;
  - each prop has a small name tag that a ray can pinch.
- **Empty-space pinch is per hand:** a pinch opens the keypad only if *that* hand's ray, grab and poke pointers are all on the void. Otherwise the other hand resting on a card would block it.
- **Flick-to-dismiss:** a flick closes the card that the flicking hand's ray was on during the last 300 ms. Every sample step must stay between 1.6 and 5 m/s in a consistent direction, so tracking jumps and teleports are not flicks.
- **Quality governor:** it drops fog sheets, motes, labels and glow before it drops frames. In the emulator it judges against the frame interval actually delivered (p10), because the desktop monitor, not the claimed 72 Hz, sets the pace.
- **Layers for props and paths:** the sealed layer is the default. If fewer than 2 nodes are sealed, or the node itself is fog, the whole web is used and the card says so ("in the whole web"). Paths fall back to the fog only with an explicit note.
- **Synthetic fixtures until Phase 2:** `public/demo/fixture-*.json` are generated by `scripts/make-fixtures.mjs`, carry generic labels, are marked `provenance.kind = "fixture"`, and show a TEST FIXTURE badge. They are replaced by real pipeline runs in Phase 2. They are not research output.
- **Research event stream:** bundled webs replay through the same events (`plan`, `source_found`, `claim`, `verified`, `edge`, `insight`, `done`) that the live server will stream, so the client has one growth path.
- **Removed scaffold pieces:** the voice-only topic entry, the LLM-guessed "reliability %" (it broke the evidence rule), and per-node ECS components. `src/voice-input.js` is kept for the optional voice extra in Phase 3.
- **V2 pivot (2026-10-20):** FogWeave becomes a news impact graph ([FOGWEAVE_V2_DELTA.md](FOGWEAVE_V2_DELTA.md), merged plan in [PLAN.md](PLAN.md)). Only the content layer changes. The world, renderer, cards, hands, props, layers and evidence readout are reused as built.
- **QRNG dropped:** there is no real need for quantum randomness. Light drift is cosmetic and uses an ordinary seeded hash (`hash01`). Later serendipity picks will use ordinary seeded random. Nothing random ever touches evidence, verdicts, rankings or paths.
- **News lights:** instanced like the web (one core mesh per kind, one glow mesh, one enlarged hit mesh), spread over a 220° arc at 1.45–2.2 m, outside the web bubble. Glow follows relevance, and dimming follows age (never below 35%, so old lights stay reachable). Pinching opens the reader card.
- **Reader-card shell:** Seal and Close work, and sealed news is stored on the device and listed in the Library. Expand and Ask are drawn but inactive, and the card says the news engine is not connected. They arrive in Phase 2/3.
- **Light fixtures:** `public/demo/lights.json` holds 12 synthetic items (badged TEST FIXTURE) until Phase 2 produces a dated real snapshot.
