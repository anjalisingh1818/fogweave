# Decisions

One line each: what was chosen, and why. Newest last.

- **Client stack:** IWSDK `@iwsdk/core` 1.0.1 (three r181 via super-three) and Vite 7.3.7, both pinned. The scaffold already used them; IWSDK is Meta's WebXR SDK with an emulator built in.
- **Emulator QA:** IWER 2.6.0 (bundled with `@iwsdk/vite-plugin-dev`) drives scripted hands through its remote-control API (`set_transform`, `look_at`, `animate_to`, `set_select_value`). These are scripted hands, not people, and not a Quest.
- **QA browser:** Playwright 1.64.1 (pinned) runs headless Chromium. The Claude Desktop browser pane throttles hidden pages to about 30 fps, so its frame numbers are useless.
- **HTTP dev mode:** `FW_HTTP=1` serves `http://localhost`, which still counts as a secure context, for desktop emulator QA. The default self-signed HTTPS is kept for headsets.
- **One driving system, no per-node ECS entities:** the web is drawn with InstancedMeshes (cores per type × layer, verdict rings, glows, an enlarged invisible hit mesh) and a few LineSegments. This keeps draw calls flat as the web grows.
- **Force layout:** a small in-house 3D force layout (`src/layout/force.js`) runs in a Web Worker. It is deterministic: seeds come from id hashes, so the same web always lands in the same shape, and results are cached by graph shape. d3-force-3d was not needed for 150 nodes.
- **Bubble shape:** a wide, shallow ellipsoid (x1.25, y0.8, z0.5) in front of the seated head. Viewed from one point, a sphere overlapped itself in depth. The radius grows (up to 1.6x) for big webs.
- **Cards:** canvas-texture panels with one mesh each. Buttons are hit-tested from the pointer's `uv`, so a whole keypad is one draw call and one interactable. Fonts are system fonts, so no font assets are needed.
- **Keypad is ray-pinch only:** with `PokeInteractable` on the panel, IWSDK 1.0.1 swallowed ray pinch-selects (seen in scripted QA). A pinch keypad is what the brief asks for. Retest poke on a Quest.
- **Prop tap fallback:** IWSDK sets `pointerEventsType = { deny: 'ray' }` on grabbables, so a far pinch cannot reach the Coin or Locket. Two fallbacks cover it:
  - a quick pinch-and-release on the prop (under 450 ms and under 4 cm of movement) counts as a tap;
  - each prop has a small name tag that a ray can pinch.
- **Empty-space pinch is per hand:** a pinch opens the keypad only if *that* hand's ray, grab and poke pointers are all on the void. Otherwise the other hand resting on a card would block it.
- **Flick-to-dismiss:** a flick closes the card that the flicking hand's ray was on during the last 300 ms. Every sample step must stay between 1.6 and 5 m/s in a consistent direction, so tracking jumps and teleports are not flicks.
- **Quality governor:** it drops fog sheets, motes, labels and glow before it drops frames. In the emulator it judges against the frame interval actually delivered (p10), because the desktop monitor, not the claimed 72 Hz, sets the pace.
- **Layers for props and paths:** the sealed layer is the default. If fewer than 2 nodes are sealed, or the node itself is fog, the whole web is used and the card says so ("in the whole web"). Paths fall back to the fog only with an explicit note.
- **Synthetic fixtures until Phase 2:** `public/demo/fixture-*.json` are generated by `scripts/make-fixtures.mjs`, carry generic labels, are marked `provenance.kind = "fixture"`, and show a TEST FIXTURE badge. They are replaced by real pipeline runs in Phase 2. They are not research output.
- **Research event stream:** bundled webs replay through the same events (`plan`, `source_found`, `claim`, `verified`, `edge`, `insight`, `done`) that the live server will stream, so the client has one growth path.
- **Removed scaffold pieces:** the voice-only topic entry, the LLM-guessed "reliability %" (it broke the evidence rule), and per-node ECS components. `src/voice-input.js` is kept for the optional voice extra in Phase 3.
- **V2 pivot (2026-10-20):** FogWeave becomes a news impact graph ([FOGWEAVE_V2_DELTA.md](FOGWEAVE_V2_DELTA.md), merged plan in [PLAN.md](PLAN.md)). Only the content layer changes. The world, renderer, cards, hands, props, layers and evidence readout are reused as built.
- **QRNG dropped:** there is no real need for quantum randomness. Light drift is cosmetic and uses an ordinary seeded hash (`hash01`). Later serendipity picks will use ordinary seeded random. Nothing random ever touches evidence, verdicts, rankings or paths.
- **News lights:** instanced like the web (one core mesh per kind, one glow mesh, one enlarged hit mesh), spread over a 220° arc at 1.45–2.2 m, outside the web bubble. Glow follows relevance, and dimming follows age (never below 35%, so old lights stay reachable). Pinching opens the reader card.
- **Reader-card shell:** Seal and Close work, and sealed news is stored on the device and listed in the Library. Expand and Ask are drawn but inactive, and the card says the news engine is not connected. They arrive in Phase 2/3.
- **Light fixtures:** `public/demo/lights.json` holds 12 synthetic items (badged TEST FIXTURE) until Phase 2 produces a dated real snapshot.
- **Phase 2 backend shape:** FastAPI + an in-house orchestrator with role agents (Summarizer, Extractor, Verifier, ImpactAnalyst), each behind one `run() -> Pydantic` interface. Agno was dropped for now: Groq cannot combine JSON mode with tool calls, and the scaffold's agent hid the steps. The interface stays small, so an agent framework can be swapped back in. Source search is our own adapters, not agent tools, so every request is paced and cached.
- **LLM chain:** `openai/gpt-oss-120b`, then `openai/gpt-oss-20b`, then `qwen/qwen3.8-27b` on the Groq free tier. Llama 3.3 70B is no longer served to the key (checked 2026-10-20).
  - Strict `json_schema` structured outputs; at most 2 retries; results cached by input hash.
  - Roles prefer different models (summarizer and verifier use 20b) because each model has its own 8K tokens/minute.
  - Daily usage persists across restarts.
- **Sources live:** Wikipedia Current events (with the outlets it cites), GDELT DOC 2.0, Hacker News and arXiv. Wikidata for linking and Wikipedia leads for corroboration. OpenAlex is skipped (needs a key). Terms and limits are in [SOURCES.md](SOURCES.md).
- **GDELT rate-limit detection:** GDELT answers over-limit requests with HTTP 200 plain text, which we treat as a rate limit, with a 90 s host cooldown.
- **Quotes must be verbatim:** every quote the LLM returns is checked against the text it came from (normalised whitespace and quotes, 25 words or fewer). Unverifiable claims, relations and entities are dropped and counted. Quotes from Wikipedia's portal summary are credited to Wikipedia, not to the outlet.
- **Impact labels enforced in code:** an "inferred" link whose basis ids do not exist is demoted to speculative. Impact sources are resolved to known entities by exact match, then token overlap (0.5 or more); otherwise first hops attach to the main event.
- **Evidence threshold:** "Well supported" needs 2 or more independent supporting domains with mass 1.3 or more (lowered from 1.6; see EVIDENCE.md).
- **Embeddings:** BAAI/bge-small-en-v1.5 via fastembed (ONNX, CPU). Set `FOGWEAVE_EMBEDDINGS=0` on small hosts to use the hashed bag-of-words fallback.
- **SciPy** (BSD) is required by networkx PageRank.
- **One shared ontology file** (`shared/ontology.v2.json`) for client and server. Added `same_as` (private context to entity, on device) and `relates_to` (speculative suggestions only).
- **Client algorithms in JS for anything personal or offline:** personalized PageRank and the evidence-weighted path. networkx on the server for pipeline and eval. Both are tested.
- **The web accumulates across expansions:** related items connect through shared entities. The **sealed layer persists** on the device (`fogweave.library.v1`); the fog does not.
- **Offline = a recorded real run:** `server/scripts/snapshot.py` records lights, reader claims and 3 expansions event by event into `public/demo/snapshot/` (dated, `provenance.kind = "pipeline"`, fictional sample persona). The synthetic topic and light fixtures are removed. A V2 synthetic stress web stays in `qa/fixtures/` for frame tests only.
- **QA:** `qa/phase2.mjs` replaces the Phase 1 script. It has a live run and an offline run with the backend blocked by Playwright routing.
- **Phase 3 (Ask):** GraphRAG on the server (`/ask`). The client sends a compact web around the focus (2 hops, 60 nodes or fewer, no private context). The server adds a small fresh search, ranks facts with embeddings, and the LLM must cite fact ids. Code keeps only real citations and marks uncited sentences as guesses. With nothing supported, the answer is "The web doesn't tell us." "Is this reliable?" is answered **locally** from the evidence breakdown, with no LLM.
- **Offline Ask:** the snapshot records answers to the three suggested questions per recorded expansion (graph-only, no fresh search). A typed question offline says it needs the live engine.
- **Evidence Pack:** built on the device (JSON-LD + PROV-O, JSONL, Markdown README with licence and attribution), zipped with fflate 0.8.3 (MIT). When online, the server validates the JSON-LD with rdflib and pySHACL and runs five SPARQL queries; `validation.json` goes into the zip. Remote `@context` URLs are refused, so the server never fetches attacker-chosen URLs. Pack metadata is a node inside `@graph`: a top-level `@id` would have turned the pack into a named graph that rdflib's default graph cannot see.
- **Insights by code** (`src/insights.js`): disagreement, single-source claims, entities shared across stories, bridges. They appear as a gentle "Noticed n" button on the status line, open when pinched, and never create nodes.
- **Workspace:** five card slots on the seated arc. Library, Notes and Lights panels can be pinned and moved slot to slot by pinch, and come back where you left them (`fogweave.workspace.v1`). Moving uses a button, not a grab handle: grabbables deny rays in IWSDK, and the button keeps panels on comfortable slots.
- **Daily briefing:** offered once a day. It picks 4 relevant lights (one per story, no archive) plus 1 "outside your bubble" chosen with an ordinary date-seeded pick among the least relevant stories. Each item shows only reported or inferred effects, never speculative. It ends with what you kept.
- **Story timeline:** lights in the same embedding cluster ("Story +n") are listed oldest first and drift closer for a while. The card says plainly that "same story" means similar text, not the same event.
- **Audio:** procedural Web Audio ambience (brown-noise wind and two soft tones, gain 0.05, 4 s fade in) after the first gesture; off in Settings. Read-aloud uses speechSynthesis where available. Voice input (Web Speech) is off by default and fills the keypad for confirmation.
- **Gentle motion setting:** slower drift for nodes, lights and fog; softer reveal pulses.
- **V2 update (§3b, §12), branch `v2-news`:** the V1 topic mode had already been replaced by the first V2 delta, and nothing was deployed. The fallback named in §12.1 is therefore the Phase 3 news build (commit `ee8aa3e`), not topic mode.
- **Feed = curated random:**
  - The server builds a scored candidate pool (`fogweave/feed.py`): quality = 0.40 source class + 0.30 recency + 0.20 usefulness + 0.10 novelty, with near-duplicates removed and tags (news types, arXiv categories) assigned.
  - The client draws about 16 lights with seeded weighted random sampling (`src/feed.js`): never below a quality floor; at most one light per story and three per type; papers capped at a quarter (half when paper types are chosen); about 1 in 4 from outside your interests; muted topics never appear.
  - Sampling runs on the device, so it also works offline on the bundled pool.
  - Interests (news types, paper types, weighted topics, mutes, surprise) live on the device. Reshuffle and "more / less like this" adjust them. One idle light is swapped every 75 s, never one you are looking at.
- **Explore any node** (`fogweave/explore.py`, `/explore`): a definition and origin from the Wikipedia lead (CC BY-SA, attributed); parts and membership from Wikidata statements (CC0, quoted as statements with the item URL); related news only if the text names the node; related papers only if the abstract names it; and impact with the same rules as expand (basis required, persona guard, aliases are not effects).
  - The client shows about 8 new nodes per explore, with "show more", a breadcrumb trail with Back, Pin and Collapse.
  - The visible cap is 60 nodes, ranked by distance from the focus, pins and seals.
  - Touching a light also grows it (`settings.feed.autoExpand`), one at a time.
- **Look (§12.4):** news lights are warm white-gold, with the kind shown by shape and glow pattern (latest = steady star, research = breathing orb, archive = dim orb). They leave short fading trails and brighten when a fingertip comes within 35 cm.
  - Links carry small light pulses flowing from cause to affected; speed and brightness follow the label (reported > inferred > speculative).
  - **Ambient motes are faint white, red and blue, tiny and purely decorative: they carry no meaning.** Evidence colours appear only on node rings and links.
  - Calm mode (Settings → Gentle motion) cuts motes by 60%, glow by 30% and drops trails. All motion stays well under 3 flashes per second.
  - Budget: 300 motes, 16–20 lights, 60 nodes, 300 links and pulses. The governor drops decoration first.
- **Persona-chasing guard:** the eval showed speculative impact chains forced toward the reader's context ("migrant deaths → insurance → energy prices"). The impact prompt now forbids building chains to reach the context, and code drops speculative links that land on context labels.

## V2 master, Stage A (2026-10-21, after the live test of 21 Oct)

- **No third-party calls (F6):** IWSDK loads hand and controller models from the jsdelivr CDN when XR starts. That was the request a blocker refused, and it would fail offline. The four models are vendored in `public/vendor/input-profiles` (MIT), and the entry point rewrites that CDN prefix at `fetch` (a LoadingManager hook did not reach the input package's own copy of three.js). `qa/no-third-party.mjs` checks it, with hands and with controllers.
- **Voice loads only when used:** the voice module is imported on first use, and support is tested with an `in` check, so nothing speech-related runs at page load. The app never asks for the microphone unless the reader turns voice on and presses Mic.
- **Reader card is compact by default (F3):** source type, LIVE or SNAPSHOT (date), headline, the real outlet and date, one summary line, Touches me? / More like this / Less like this, and Seal / Expand / Ask / Details / Close. Details grows the card to show claims, quotes, the link and Listen. ⇄ moves it.
- **No overlaps by construction (F4):** card text flows top-down into the space above the button rows and is shortened to fit; every drawn box is recorded and `qa/stage-a.mjs` checks for overlaps at 1280×800, 1024×768 and 800×600.
- **Flat page = desktop fallback (F5):** without a headset, cards sit in two columns at the screen edges, on the side away from what they belong to, scaled to fit, at most two at a time. The light arc (±117°) is squeezed into the window's view, lights in the upper part. A missed click does nothing (in VR, pinching empty space still opens Find). A light stops drifting while a pointer or hand is on it.
- **Aimed picking:** node hit spheres are enlarged so small nodes are easy to touch, which let a hub's sphere swallow its neighbours. A click now picks the node whose centre is closest to the line from the pointer through the hit point, relative to its size.
- **Status bar and props moved apart:** the status bar (breadcrumb and Back) sat inside the web's bubble and right above the Locket and Coin, so a hand reaching for Back could grab a prop or hit a node instead. The bar is now 0.5 m ahead and 0.45 m down, the web moves out as it grows (it never reaches the bar), and the props sit further out to the sides (±0.36 m).
- **Real source first (F9):** cards show the outlet (e.g. reuters.com) with its date and link; the aggregator that found it reads "found via Wikipedia Current events". Every item shows a source-type badge (news / paper / archive; filing and dataset are ready for Stage B) and LIVE or SNAPSHOT with the snapshot date.
- **Explore uses a node's own Wikidata id** and matches Wikipedia titles without accents ("Raul Castro" = "Raúl Castro"). When open sources have nothing more on a node, its card says so.
